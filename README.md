## 🏛️ Architecture & System Overview

- **Backend**: FastAPI (Python 3.12+), Pydantic v2 schemas, SQLAlchemy 2.0 ORM, and dependency injection (`get_db`).
- **Database**: SQLite with foreign keys and Alembic migration tracking.
- **Frontend**: React 18 with Axios for all REST API communication, Vite dev server, and real-time WebSocket syncing.
- **SDK**: Auto-generated Python Client SDK produced by `@openapitools/openapi-generator-cli`.
- **Real-Time Engine**: WebSocket broadcaster (`/ws`) providing live updates across connected clients.

## ⚡ Features & Trick Logic Implementation

### 1. Doctor Management
- `POST /doctors/`: Add a doctor with shift working hours (`start_hour`, `end_hour`).
  - Validates `0 <= start_hour < end_hour <= 24`.
- `GET /doctors/`: Retrieve all registered doctors.
- `GET /doctors/{id}`: Retrieve details of a specific doctor.
- `GET /doctors/{id}/availability`: Dynamic query for a doctor's hourly slots on a specified date (`YYYY-MM-DD`). Automatically computes `is_available: true/false` for each slot.

### 2. Appointment Booking & Trick Logic (Hidden Complexity)
- `POST /appointments/`: Book a patient consultation slot.
  - **Trick Logic 1: Double-Booking Prevention**:
    - Rejects duplicate bookings for the same doctor at the same slot with `409 Conflict` (or `400 Bad Request` with descriptive error).
    - Allows different doctors to have appointments at the same timestamp without cross-doctor interference.
  - **Trick Logic 2: Working Hours Enforcement**:
    - Rejects appointment requests outside the doctor's declared working shift with `400 Bad Request`.
    - Handles boundaries: A doctor working 09:00–17:00 allows slots 09:00 through 16:00 (1-hour consultations ending by 17:00), and rejects 08:00, 17:00, or 18:00.
  - **Integrity Validation**: Verifies that the specified doctor exists (returns `404 Not Found` if missing).
- `DELETE /appointments/{id}`: Cancel an appointment.
  - Validates existence (returns `404 Not Found` if invalid).
  - Automatically re-opens the freed slot for subsequent bookings.
- `GET /appointments/`: List all appointments with optional filters (`doctor_id`, `patient_name`).
- `GET /stats`: Real-time system analytics (total doctors, appointments, upcoming consults, and clinician caseloads).

## 🚀 Quick Start (Windows Batch Scripts)

The project includes the two required Windows batch scripts:

### 1. Development Setup (`setupdev.bat`)
Run this from the project root to set up the Python virtual environment, install backend packages, run Alembic migrations, and install frontend dependencies:
```cmd
setupdev.bat
```

### 2. Execution Script (`runapplication.bat`)
Run this to launch both the FastAPI backend (`http://localhost:8000`) and the React frontend (`http://localhost:3000`):
```cmd
runapplication.bat
```

## 🗄️ Database Migrations & Seeding

The database adheres strictly to the required SQLite schema:
```sql
CREATE TABLE doctors (
    id INTEGER PRIMARY KEY,
    name TEXT,
    specialization TEXT,
    start_hour INT,
    end_hour INT
);

CREATE TABLE appointments (
    id INTEGER PRIMARY KEY,
    doctor_id INT,
    patient_name TEXT,
    slot TIMESTAMP,
    FOREIGN KEY(doctor_id) REFERENCES doctors(id)
);
```

### Running Migrations:
```cmd
alembic upgrade head
```

### Seeding Test Data:
To populate initial sample doctors and appointments:
```cmd
sqlite3 healthcare.db < seed_data.sql
```
*(Or via python sqlite3 as shown in setup steps).*

## 📦 Platform Python SDK

The Python SDK is generated using the official `@openapitools/openapi-generator-cli`:

### Command to Regenerate SDK:
```bash
npm install -g @openapitools/openapi-generator-cli
openapi-generator-cli generate -i http://localhost:8000/openapi.json -g python -o health_sdk --additional-properties=packageName=health_sdk
```

### Expected SDK Usage (As specified in challenge):
```python
from health_sdk.api.doctors_api import DoctorsApi
from health_sdk import ApiClient

# Initialize client pointing to http://localhost:8000
client = ApiClient()
api = DoctorsApi(client)

# Example: List all doctors
doctors = api.list_doctors()
for doc in doctors:
    print(f"Doctor: {doc.name} - Specialty: {doc.specialization} ({doc.start_hour}:00 to {doc.end_hour}:00)")
```

## 🌐 Frontend Client (ReactJS)

Built with React 18 and styled with custom responsive CSS:
1. **Doctors & Availability View**:
   - Lists all doctors with medical specialties and working hours.
   - Interactive date picker to view 1-hour slots for any selected date.
   - Slots are color-coded:
     - 🟢 **Available (Free)**: Clickable to directly open pre-filled booking modal.
     - 🔴 **Booked**: Labeled and disabled to prevent double booking.
2. **Appointments View**:
   - Live searchable table of all confirmed appointments.
   - Filter by patient name or doctor.
   - "Cancel" button to immediately revoke an appointment and free up the slot.
3. **Analytics Dashboard (Bonus Feature)**:
   - High-level KPIs: Total Doctors, Total Bookings, Upcoming Appointments, Average Caseload.
   - Physician Appointment Distribution chart visualizing caseload volume per clinician.
4. **Real-Time Sync (Bonus Feature)**:
   - Bi-directional WebSocket link (`/ws`).
   - Automatically synchronizes availability and appointment tables across all open tabs when any user books or cancels an appointment.
